# 성산 외곽·남쪽 확장 맵

사용자가 제공한 지도·항공사진·거리뷰를 참고한 SUMO 도로망입니다.
실제 측량 좌표를 그대로 옮긴 모델은 아닙니다. 처음에는 일출로 약 600m 구간에 맞췄으며,
현재는 전체 길이 축소 요청에 따라 압축한 시뮬레이션용 배치입니다.

## 현재 구조

- 북쪽 외곽 폐루프는 유지하고, 그 안쪽의 마을 연결도로는 삭제했습니다.
- 서쪽 중간 진출입로와 가상 식당·진입로·진출로·주차장은 삭제했습니다.
- 로터리는 반시계 방향 2차로이며, 삭제된 내부 도로로 향하던 북동쪽 출입구도 없앴습니다.
- 로터리 서쪽 진출입 도로는 왕복 4차로(방향별 2차로)입니다.
- 왼쪽 로터리~남쪽 사거리는 굴곡 없는 왕복 2차로 직선입니다.
  북상 차로는 로터리 앞에서 1→2차로로 넓어지고, 남하 차로는 1차로입니다.
- 오른쪽 남북 도로는 기본 왕복 4차로입니다. 삼각형 접근부에서 북상 차로만
  2→1차로로 줄어듭니다. 이 구간의 남하 차로는 2차로입니다.
- 하단 연결도로는 왕복 4차로이며, 남쪽 사거리에 신호가 있습니다.
- 삼각형 왼쪽 연결도로는 남하 2차로·북상 1차로입니다. 남하 좌회전은 중간 대각선 연결로에서만 가능하고,
  맨 아래에서는 남쪽 도로로 직진만 가능합니다.
- 외부 생성·소멸 경계는 7곳, 일반 차량 경로는 42개입니다.

기본 시연 경로 `outermost`는 북서쪽 사거리 동쪽 100m → 사거리 → 하마보 앞 → 로터리 → 남쪽 직선 → 하단 사거리·삼거리 →
오른쪽 도로 북상 → 작은 합류부 → 좁은 해안 연결도로 → 북쪽 외곽 → 출발점 복귀입니다.
출발과 도착은 `north_return`의 0번 차로, 차로 시작점에서 약 48.905m 지점으로 동일합니다.
이는 북서쪽 사거리(`northwest`)까지 남은 도로 거리가 100m인 위치입니다.
`EGO_START_ANCHOR_NODE`·`EGO_START_ANCHOR_EDGE`·`EGO_START_DISTANCE_M`로 지정하며,
기존 경로의 시작 순서만 옮겨 같은 방향으로 순환합니다. 주행 중 측정한 사거리까지의 거리도 100.0m였습니다.
마을 안쪽이나 일출로 지름길을 이용하지 않는 최외곽 폐루프이며 길이는 약 1.06km입니다.
`expanded`는 같은 경로의 호환 별칭이고, `original`은 기존 북쪽 짧은 경로입니다.
빨간 차량은 경로 검증용 SUMO 운전자 모델이며 학습된 AV가 아닙니다.

## 전체 길이 압축

일반 도로의 좌표 축척을 최초 배치의 47%로 줄였습니다. 직전 55% 배치보다 약 15% 더 작습니다.
로터리 북쪽(y=858 위쪽)은 세로 길이를 추가로 90%로 압축하고, 원본 그림의 y=1200 아래쪽은
세로 길이를 원래의 15%로 압축했습니다. 북쪽 외곽과 남쪽의 긴 도로를 함께 줄였습니다.
차로 폭과 로터리·삼각형·동쪽 분리 진입로의 회전 공간은 별도로 보존합니다.
삼각형 합류부의 물리적 길이·폭은 최초 보정 배치의 80%입니다.
빗금은 회전 차선과 겹치지 않도록 별도로 보정했습니다.
외부 생성·소멸 도로까지 포함한 전체 범위는 약 가로 414m × 세로 369m입니다.

| 구간 | 조정 전 | 조정 후 |
| --- | ---: | ---: |
| 기본 전체 루프 | 1,294.0m | 1,056.8m |
| 전체 범위 가로 × 세로 | 484m × 432m | 414m × 369m |

전체 루프는 교차로 연결 차선을 포함합니다. 차로 폭·차로 수·교차로 내부 크기는 유지하고
사이를 잇는 도로 길이를 줄였습니다.
남쪽 오른쪽 도로와 하단 삼거리를 정렬하고 마을 연결로·동쪽 본선을 직선화한 길이를 포함합니다.
`config.py`의 `GLOBAL_LENGTH_FACTOR`(현재 0.47), `NORTH_LENGTH_FACTOR`(현재 0.90),
`SOUTH_LENGTH_FACTOR`(현재 0.15),
`MERGE_LENGTH_FACTOR`(삼각형 구간, 현재 0.80)로
압축 정도를 바꿀 수 있습니다. 작은 값일수록 짧아집니다. 원본 좌표는 파일 위쪽에 남아 있고,
파일 아래쪽에서 변환을 한 번 적용하므로 실행할 때마다 누적해서 줄어들지 않습니다.

## 차로 전환·정지선·동쪽 삼거리

- 전체 도로의 중간 점과 단순 연결 지점은 접선이 이어지는 곡선으로 보간합니다.
  `config.py`의 `ROAD_CURVE_HANDLE_M`(24m)과 `ROAD_CURVE_STEP_M`(3m)으로 곡률과 간격을 조절합니다.
  작은 삼각 교차로는 제어 길이를 3m로 제한하고, 기존 합류 곡선과 차로 전환부는 보존합니다.
- `markings.py`에서 실제 차로 폭과 교차로 영역을 합친 하나의 포장면을 만듭니다.
  검은 면과 흰 외곽선은 이 포장면을 함께 사용합니다. 차로 사이의 가느다란 틈은 합치고,
  로터리·지정 교통섬·큰 필지의 내부 영역은 보존합니다.
- 검은 도로 면은 구멍을 보존하는 삼각 분할로 그리며, 흰 테두리는 같은 면의 경계입니다.
  점선은 실제 차로 경계에서 3m 표시·3m 간격으로 그립니다. 차량 생성 지점에 가짜 가로
  정지선을 추가하지 않으며, 실제 신호·양보 표시는 SUMO에서 유지합니다.
- 도로 면은 각 차로 중심선을 차로 폭만큼 펼쳐 합칩니다. 좁은 굽힘에서 점을 생략하는
  오프셋 함수를 포장면 생성에 사용하지 않습니다. 생성 시 모든 내부·외부 차로의 전체 폭이
  포장면에 들어가는지 검사하며, 누락 면적이 허용 오차를 넘으면 생성을 중단합니다.
- 도로 가장자리의 렌더링 돌출 부분도 같은 포장면을 기준으로 정리합니다.
  곡선은 3m 간격으로 생성해 짧은 선분에서 생기던 검은 잔상을 줄였습니다.
  흰선은 폭 0.12m의 면으로 그립니다. 도형 연산에는 Shapely 2.1 이상을 사용합니다.
  노란 중앙선도 폭 0.15m의 면으로 생성해 직선 구간에서 연속으로 표시합니다.

- 로터리 남쪽 북상 1→2차로, 오른쪽 북상 2→1차로, 동쪽 삼거리 진입 1→2차로는
  각각 18m 길이로 폭을 점진적으로 바꾸는 구간입니다. 외곽선과 점선도 도로 폭을 따라 이어집니다.
- 동쪽 삼거리는 최신 항공사진·거리뷰를 기준으로 본선을 곧게 정렬했습니다.
  진입로는 확장부의 접선을 따라 넓어진 뒤, 부드러운 곡선으로 좌회전·우회전 차로로 나뉩니다.
  우회전 차로의 시작·끝 형상을 차로 폭에 맞게 옮겨 분기부의 과도한 겹침을 없앴습니다.
  분기점은 본선 접속부에서 남쪽 25m, 우회전 합류점은 본선 방향으로 22m 떨어져 있습니다.
  분기점은 신호·양보가 없는 차로 분리 지점이고, 좌회전 일시정지와 본선 우회전 양보를 적용합니다.
  남하 차량이 이 분기점에서 우회전 우회 차로로 되돌아가는 연결도 제거했습니다.
- 오른쪽 두 차로 진입부와 우회전 차로는 하나의 직선 축을 사용합니다.
  차로 확장부가 끝난 뒤부터 우회전 분기를 지난 지점까지, 약 36.2m의 바깥 경계를 직선으로 연결했습니다.
  일방통행 차로의 기준선은 같은 축에 수직으로 한 차로 폭만큼 옮겨 실제 주행 차로와 외곽선을 일치시킵니다.
  본선 합류 직전만 완만하게 연결하고, 끝의 8m는 본선과 평행한 직선입니다.
  분기·합류부의 포장면은 실제 내부·외부 차로 폭으로 만들고, 자동 교차로 도형의 불필요한 돌출은 제외합니다.
  세 진입부 정지선은 차로 진행 방향에 수직인 흰 막대로, 우회전 차로는 세 개의 흰 양보 점선으로 표시합니다.
  기본 막대가 겹치지 않도록 해당 네 위치만 레이어 210에서 가리고, 경계선·중앙선과 표시를 211에서 다시 그립니다.
  차량 레이어(340)보다 낮아 차량은 정상적으로 보입니다.
  [SUMO 1.27.1 표시 코드](https://github.com/eclipse-sumo/sumo/blob/v1_27_1/src/guisim/GUILane.cpp)를 기준으로 기본 통행 막대의 표시 높이를 확인했습니다.
- 사용자 스케치·거리뷰에 맞춰 왼쪽 진입부 끝을 본선에 수직으로 정렬했습니다.
  왼쪽 정지선은 본선과 평행한 사선으로 놓이고, 중앙선은 이 정지선에서 끝납니다.
  오른쪽 양보선은 기존 위치에서 진입 방향 반대로 7.5m 옮겼습니다.
  아래 분기부에는 정지선을 두지 않고, 반경 0.6m의 국소 포장 보정으로 곡선의 작은 파임을 메웠습니다.
  분기점 중심에서 9m 범위까지 바깥 경계를 보정해 차로 끝의 얇은 틈과 안쪽으로 튀어나오는 흰 선을 없앴습니다.
  두 갈래 차로가 실제 폭으로 겹치지 않는지도 검사합니다.
- 교통섬은 고정 삼각형 그림 대신 실제 차로 사이의 빈 영역을 사용합니다.
  노란 테두리는 섬 안쪽으로 0.55m 물리고, 빗금은 그 안에서만 생성합니다.
  횡단보도는 전체 맵에서 모두 제거했으며, 생성 코드와 미리보기에서도 만들지 않습니다.
  `ROAD_STOP_OFFSETS`는 본선 두 진입부 4.5m, 왼쪽 진입부 1.5m, 오른쪽 양보 차로 12m입니다.
  정지선 앞 좌회전 외부 차로는 17.08m이며, 실제 차량 정지도 새 정지선 위치를 사용합니다.
- 오른쪽 차로 감소부는 두 차로가 하나로 연결되는 [SUMO의 지퍼 합류](https://sumo.dlr.de/docs/Networks/PlainXML.html)입니다.
  별도의 교차로나 정지 신호를 두지 않았습니다.
- SUMO 화면의 `realisticLinkRules`를 켜서 직진 우선 통행·지퍼 합류의 불필요한 흰 가로선을 숨겼습니다.
  실제 신호등의 적색·황색·녹색 표시와 부도로의 양보 표시는 유지합니다.
- 차량은 `vehicleQuality=2`로 승용차 모양을 표시합니다. 사용자 화면 스타일의 기본값인
  삼각형 기호 표시로 바뀌지 않도록 명시했습니다.
- 사용자가 표시한 `east_signal_approach_0`의 화살표만 숨겼습니다. `HIDDEN_LANE_ARROWS`로 지정하며,
  차량의 통행 연결은 유지합니다.
- 차로와 교차로 내부 연결선의 실제 폭을 따라 포장면을 추가해 연결부의 초록색 틈을 메웠습니다.
  로터리 안쪽 경계, 바깥쪽 연결 곡선, 순환 차로 점선도 연속으로 정리했습니다.
- 로터리 순환 차로와 진입부의 기본 꺾임 화살표는 간결한 진행 방향 화살표로 교체했습니다.
  동쪽 진입 포켓의 두 차로에는 좌회전·우회전 화살표를 따로 배치했습니다. 정지선 직전의
  짧은 차로에는 기본 좌회전 표시를 사용합니다. `CUSTOM_ARROW_EDGES`, `CUSTOM_LANE_ARROWS`로 지정합니다.
- 우회전 우회 차로는 직선과 합류 곡선을 사용합니다. 남쪽 오른쪽 도로는 아래 삼거리를 위쪽과 같은 축에
  맞춰 직선으로 연결했고, 삼거리 아래 큰길도 수평 직선으로 정렬했습니다.
  `STRAIGHT_STREETS`의 마을 연결로·동쪽 본선·남쪽 오른쪽 도로는 곡선 보간을 생략합니다.
- 마주 오는 방향을 나누는 중앙선은 전체 도로에서 노란 실선입니다. 같은 방향 차로 사이의 점선과
  도로 바깥 경계선은 흰색입니다. 로터리는 일방향이므로 내부 차로 구분선은 흰색입니다.
- 삼각형 중간 접속부의 중앙선은 양방향 대각선 연결로에서 위쪽 양방향 도로로 이어집니다.
  아래쪽 일방통행 진입로의 가장자리를 중앙선에 연결해 주행 경로를 가로지르지 않도록 했습니다.
- 로터리 북쪽 진입부의 노란 네모는 짧은 접속부에서 중앙선을 잘못 이어 그린 오류였습니다.
  북쪽 도로를 하나로 합쳐 제거했고, `west_lower` 좌표는 보호구역 표지 위치로 남겼습니다.
  `roundabout_approach`라는 짧은 도로는 제거했습니다.
- 로터리 동쪽 일출로와 골목의 분기점(`triangle_west`)은 우회전 진입·진출 구조입니다.
  본선 중앙선을 분기점 안에서도 연속으로 그려 본선에서 골목으로 좌회전하거나 골목에서 반대편 차로로
  좌회전하지 못하게 했습니다. 골목 출구 `minor_west_rev`는 `main_sweep`으로 우회전만 허용합니다.
- 삼각형 위쪽 가로 구간, 오른쪽 위·아래 구간은 직진 연결만 허용하고 노란 실선을 이어 표시했습니다.
  해당 세 곳에서 왼쪽 가지로 꺾어 들어가는 연결은 제거했습니다.
  왼쪽 윗모서리의 중앙선은 `minor_west`에서 `triangle_west_upper`로 휘어 내려가도록
  매끄러운 곡선으로 이어집니다.
- 삼각형 왼쪽의 `minor_west`, `triangle_west_upper`, `triangle_west_leg`는 모두 남하 2차로,
  역방향은 북상 1차로입니다. 중간의 `triangle_west_upper` 1번 차로에서는 `triangle_cross`로
  좌회전할 수 있고, 0·1번 차로 모두 아래로 직진할 수 있습니다.
  맨 아래의 `triangle_west_leg`는 두 차로 모두 `coast_merge_approach`로 직진만 가능합니다.
- 동쪽 삼거리의 아래쪽 진입로는 `east_turn_pocket_rev`에서 약 15m 동안 2차로입니다.
  1번 차로는 `east_signal_approach_rev`로 갈라져 정지선에서 일시정지한 뒤 좌회전합니다.
  0번 차로는 별도 우회 차로 `east_right_slip`으로 갈라져 본선 북동쪽으로 진입합니다.
  두 경로 사이에 노란 삼각형 분리 구역을 표시했습니다.
  분기점을 남쪽으로 옮겨 좌회전 정지선 앞의 짧은 차로와 우회전 분리 공간을 확보했습니다.
- 좌회전 차로와 본선 양쪽은 전방향 일시정지 규칙을 따릅니다. 우회전 우회 차로는 신호를 받지 않으며,
  `east_cross`에서 본선 차량에 양보한 뒤 합류합니다. 본선 교통 상황에 따라 정지할 수 있습니다.
- 좌회전 제한 사진은 로터리 동쪽 골목 분기점에 해당합니다. 동쪽 신호 삼거리에 잘못 적용했던
  좌회전 제한은 해제하여, 이 신호 삼거리의 원래 좌회전·본선 진입 전용 차로를 유지했습니다.

## 사진에 맞춘 일출로·합류부

이전 버전에서 큰 삼각형 전체를 작은 교통섬처럼 단순화했던 구조를 수정했습니다.

1. `main_sweep`, `east_main`은 넓게 휘는 일출로의 연속 왕복 4차로입니다.
2. 그 아래 빈 땅의 아래쪽을 `minor_west`, 오른쪽을 `minor_coast`가 지납니다.
   왼쪽 연결도로는 남하 2차로·북상 1차로, 오른쪽 연결도로는 방향별 1차로이며 차로 폭은 3m입니다.
3. 합류부 확대사진에 맞춰 왼쪽은 거의 직선, 오른쪽은 대각선으로 내려오는 비대칭 형태입니다.
   위쪽 두 진입점 사이에 `triangle_top`, 양 옆에 `triangle_west_upper`, `triangle_east_upper`가 있습니다.
4. 중간의 `triangle_cross`는 양방향으로 통행 가능한 대각선 연결로입니다.
   이 연결로가 위쪽의 넓은 삼각 도류구역과 아래쪽의 길쭉한 도류구역을 나눕니다.
   `triangle_west_leg`, `triangle_east_leg`는 그 아래에서 남쪽 도로로 합류합니다.
5. 합류부 전체를 포장면으로 표시하고, 위쪽은 네 겹 노란 삼각 윤곽과 빨간 시선유도봉,
   아래쪽은 길쭉한 노란 윤곽으로 표시했습니다. 차선 폭과 SUMO 회전 경로를 고려해
   빗금 위치를 보정했으며, 사진의 형태를 근사한 것으로 실측 좌표는 아닙니다.

사용자가 표시한 구간의 차로와 방향은 다음과 같습니다.

| 사진 표시 | 도로 | 통행 방향·차로 |
| --- | --- | --- |
| 위쪽 빨간색 | `triangle_top_rev` | 오른쪽 → 왼쪽, 일방통행 1차로 |
| 오른쪽 아래 빨간색 | `triangle_east_leg_rev` | 아래 → 위, 일방통행 1차로 |
| 왼쪽 도로, 최신 수정 | `triangle_west_upper`, `triangle_west_leg` 및 역방향 | 남하 2차로 + 북상 1차로 |

일방통행의 반대 방향 차선은 도로망에서 제거했습니다. 오른쪽에서 남쪽으로 내려가는
일반 차량은 대각선 연결로와 왼쪽 왕복 도로를 이용합니다. 기본 시연 차량은
오른쪽 아래 일방통행을 아래에서 위로 통과합니다.

빗금과 시선유도봉은 시각 요소이며, 주행 경로는 이를 둘러싼 도로 연결로 제한합니다.
이 구간은 무신호이며, 주도로/부도로 우선순위와 SUMO의 양보 규칙으로 통행합니다.
좁은 구간의 정확한 차로 유도·개별 회전 금지와 실측 형상은 확인되는 자료에 따라 추가 보정할 수 있습니다.

## 속도·신호

- 마을 외곽 도로 50km/h, 왕복 4차로 주도로 60km/h, 로터리 20km/h.
- 범하다 부근~보룡제과의 서쪽 어린이보호구역은 양방향 30km/h.
  순간 속도 흔들림을 고려해 시뮬레이터 제어 목표는 28.5km/h입니다.
  보호구역 표지 직전의 짧은 `start_south` 구간에서도 미리 감속하도록 제어 목표를 적용했습니다.
- 이전 은행~CU 내부 연결로는 내부 도로 삭제 요청에 포함되어 없어졌습니다.
- 도류구역 주변과 중간 대각선 연결로는 30km/h로 설정했습니다.
- 신호등은 왼쪽 아래 남쪽 사거리(`south_cross`, `signal_south`) 1곳만 남겼습니다.
- 서쪽 은행(`bank`), 동쪽 삼거리(`triangle_northeast`), 북동쪽 삼거리(`godeungeo`)는
  흰 정지선과 `allway_stop`을 적용합니다. 모든 진입 차량은 정지 후 순서·양보 규칙에 따라 통행합니다.
  은행 부근은 내부 연결도로 삭제 후 직진 통행만 있는 구간입니다.
- 남쪽 사거리 신호는 임시 90초 주기·황색 3초·전방향 적색 2초입니다.
- 변경 전 신호등 4곳 버전은 상위 `final_project_backup2`에 보존했습니다.
  맵 소스·생성 파일 등 주요 26개 파일의 내용이 변경 전 현재 맵과 일치하는지 확인했습니다.

## 검증

현재 출발 위치·사진 기준 동쪽 삼거리를 적용한 버전의 30분 점검에서
큰 루프(약 1,056.8m)는 125.6초에 완주했고, 일반 차량 경로 42개가 모두 통과했습니다.
충돌·강제 이동 0건, 보호구역 최고속도 28.512km/h였습니다. 급제동 경고는 10건이 있었습니다.
로터리 남쪽 북상 확장 차로 87대, 오른쪽 북상 축소 차로 37대의 통행을 관측했습니다.
동쪽 좌회전 정지선 차로 9대, 우회전 양보 차로 26대가 통과했습니다.
은행 150대·동쪽 삼거리 80대·북동쪽 삼거리 105대의 정지선 앞 정지를 관측했습니다.
남쪽 사거리 신호에서는 69대가 적색 정지했습니다.
골목 분기점의 본선 직진 9대·골목 출구 우회전 27대, 삼각형 맨 아래 직진 67대를 확인했고
금지 회전은 관측되지 않았습니다.
네트워크 신호 제어기가 `signal_south` 하나뿐인지 확인했습니다. 나머지 세 곳은
`allway_stop`이며 모든 진입 연결이 정지 상태(`w`)를 사용합니다. 검증 결과는
`generated/signal_check.json`에 기록했습니다.
짧은 접속 도로를 건너뛰어 오판하지 않도록 완주·구간 통과·금지 회전 검사는
SUMO의 실제 경로 진행 인덱스를 이용합니다.
기존 삼각 교차로의 차선 중심선과 위·아래 빗금 구역 사이의 간격은 각각 1.889m·1.662m였습니다.
새 동쪽 교통섬 테두리와 전체 차로의 가장자리 사이 최소 간격은 0.488m입니다.
왼쪽 정지선과 본선 방향의 평행 오차는 0.007도이며, 좌·우 진입 차로의 실제 폭은 서로 겹치지 않습니다.
횡단보도 도형과 실제 횡단보도 도로가 모두 0개인지 검사했습니다.
오른쪽 직선 경계의 기준선 오차는 최대 약 0.0082m로, SUMO 좌표 반올림 범위입니다.
동쪽 형상·경로 및 백업2 원본 26개 파일 유지 여부는 `generated/entry_geometry_check.json`에 기록했습니다.
검은 포장면의 삼각 분할과 원본 영역 차이는 0㎡였으며, 흰 외곽선이 공통 경계를 벗어나는
구간이 없는지 확인한 결과는 `generated/marking_check.json`에 기록했습니다.
265개 내부·외부 차로의 전체 폭을 검사해 누락 면적은 0㎡였습니다(경계 허용 오차 3cm).
남쪽 오른쪽 구간은 방향별 2차로, 남쪽 북상 합류는 기존 2→1차로 연결을 유지합니다.

이전 버전(대각선 연결로 추가 전)은 일반 차량만 1시간 × 난수 시드 10개로 측정해 7,140대가 모두 도착했고,
물리적 충돌·강제 이동 0건, 급제동 경고 76건이었습니다.
설정 수요는 경계당 100대/시간으로 총 700대/시간입니다.
경로별 최초 차량이 0초에 투입되므로 실제 생성은 회당 714대입니다.

```powershell
python evaluate_traffic.py --seeds 10 --seconds 3600
```

10개 시드 결과는 이전 도로망의 기록이며, 현재 도로망의 반복 측정 결과로 사용할 수 없습니다.
HV 충돌률과 학습 AV의 에피소드별 충돌률은 다른 지표입니다.
`generated/check_report.json`에 맵 점검 결과, `results/traffic_baseline_*/report.json`에 반복 측정 결과를 보관합니다.
이전 버전의 측정 폴더도 이력으로 남아 있으므로 네트워크 해시와 설정 사본을 확인하세요.

## 수정·보관

- `config.py`: 좌표·차로·속도·신호·경로·빗금 구역과 유도봉 위치.
  `ROAD_LANE_OVERRIDES`는 방향별 차로 수를 지정합니다.
  `LANE_CONNECTION_RULES`는 전용 차로별 진출 방향, `STRAIGHT_ONLY_CONNECTIONS`는 직진 제한,
  `RIGHT_ONLY_CONNECTIONS`는 우회전 제한,
  `LANE_TAPERS`는 차로 전환부 형상과 폭을 지정합니다.
- `builder.py`: 도로망과 차량 경로, 시각 요소 및 미리보기 생성.
- `generated/`: 실행 시 다시 생성됩니다. 여기를 직접 편집하면 다음 실행에서 덮어씁니다.
- 맵을 백업하려면 `maps/`와 `view_map.py`, `requirements.txt`를 함께 복사하세요.

기존 `train.py`, `test.py`, `collect_pomdp_data.py`는 아직 원본 고속도로 예제용입니다.
새 맵에서 AV를 학습하려면 관측·행동·보상·경로와 종료 조건을 연결하는 후속 작업이 필요합니다.
