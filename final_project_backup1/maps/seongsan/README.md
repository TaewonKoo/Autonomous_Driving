# 성산 고성리 폐루프 맵

사용자가 첨부한 고성리 항공사진의 빨간 경로를 기준으로 만든 SUMO 도로망입니다.
지도상의 형태와 연결 관계를 본뜬 초기 모델이며 실제 측량 좌표를 사용한 지도는 아닙니다.

## 경로와 차로

하마보 앞에서 남쪽으로 출발 → 로터리 북쪽 진입 → 반시계 회전 →
동쪽 어멍횟집 방면 진출 → 성산고등어 쌀밥 인근 → 북쪽 해안 구간으로 좌회전 →
서쪽으로 복귀 → 하마보 앞 좌회전 → 동일한 출발 위치로 복귀합니다.

- 서쪽 도로: 왕복 2차로, 방향별 1차로
- 로터리: 반시계 방향 2차로, 회전 차량 우선
- 로터리 북동쪽: 보룡제과–사계정 사이의 마을 연결로를 별도 진출입로로 연결 (왕복 2차로 가정)
- 로터리 동쪽부터 성산고등어 쌀밥 방면: 왕복 4차로, 방향별 2차로
- 북쪽 해안·복귀 구간과 내부 연결로: 우선 왕복 2차로로 가정
- 외부 도로: 진입·진출 지점 7곳, 서로 다른 진입점과 진출점을 잇는 42개 경로

빨간 `ego` 차량은 현재 SUMO 기본 운전자 모델로 경로를 확인하는 시연 차량입니다.
정지한 빨간 식당 위치 표시점은 없앴고, 출발 위치만 초록 점으로 표시합니다.
일반 차량은 외부 경계에서 생성되어 연결로·로터리·폐루프를 이용하고 다른 외부 경계에서 소멸합니다.
일반 차량은 Krauss, IDM, EIDM, ACC 모델을 혼합합니다.
기본 수요는 진입점당 시간당 100대, 전체 700대입니다.

## 실행

`final_project` 폴더의 터미널에서:

```powershell
python view_map.py
```

SUMO 창에서 ▶를 누르면 주행합니다. 빨간 차는 기본적으로 한 바퀴를 돌고 출발 위치에서 종료합니다.
반복 주행은 횟수를 지정합니다.

```powershell
python view_map.py --laps 10
python view_map.py --netedit
python view_map.py --check --seconds 1800
python view_map.py --no-traffic
python view_map.py --background-only
```

가상환경을 사용하는 경우 `python` 대신 `.\.venv\Scripts\python.exe`를 사용하세요.
처음 실행할 때 SUMO 파일과 [도로 미리보기](preview.svg)가 생성됩니다.
도로·차량 실행 파일은 `generated/seongsan.sumocfg`입니다.

## 수정

- `config.py`: 사진 좌표, 도로별 차로 수, 속도, 교통량, 경로
- `builder.py`: SUMO 변환, 회전교차로, 일반 차량 경로, 미리보기 생성
- `generated/`: 실행할 때 재생성되므로 직접 고친 내용은 덮어씁니다.

초기 임시 축척 0.75m/픽셀에서 로터리 동쪽 출구부터 북쪽 좌회전 진입부까지는
교차로 내부 주행거리를 포함해 약 838m였습니다.
사용자가 알려준 약 600m를 기준으로 0.543344m/픽셀로 보정했습니다.
차로 폭 3.2m는 유지하고 도로 좌표와 로터리 중앙섬을 같은 비율로 줄였습니다.
정확한 생성 거리와 전체 한 바퀴 거리는 `generated/manifest.json`에 기록합니다.
현재 제한속도는 어린이보호구역 30km/h, 그 밖의 마을 도로 50km/h,
아래쪽 왕복 4차로 큰길 60km/h, 로터리 20km/h입니다.
보호구역 외 실제 제한속도·다른 구간의 실측 거리·신호 현시/시간·횡단보도·진입부 차선 유도·북쪽 차로 수는 아직 현장 자료로 보정하지 않았습니다.
내부 연결로도 사진을 참고해 단순화한 구조입니다.

## 검증과 다음 단계

30분 시뮬레이션에서 요청 경로와 출발 위치 복귀를 확인했습니다.
일반 차량 경로 42개 모두 진입·진출했고, 충돌 및 텔레포트는 0건이었습니다.
검증 상세는 `generated/check_report.json`, 도로 변환 기록은 `generated/netconvert.log`에 남습니다.
이는 설정된 수요와 고정 시드에서의 맵 점검 결과입니다.

기존 `train.py`, `test.py`, `collect_pomdp_data.py`, `view_road.py`는 아직 원본 직선 고속도로 예제를 실행합니다.
새 맵에서 학습하려면 `env/sumo_env.py`의 단일 Edge 기반 차량 배치·도착 판정·차선 탐색과
관측·행동·보상을 교차로/다중 Edge에 맞게 연결하는 후속 작업이 필요합니다.

위치 확인 참고: [제주관광공사 어멍횟집 안내](https://www.visitjeju.net/kr/detail/view?contentsid=CNTS_000000000020500).
실제 도로 형태의 기준 자료는 사용자가 제공한 두 번째 항공사진입니다.

## 일반 차량만의 충돌률 측정

프로젝트 루트에서 `python evaluate_traffic.py --seeds 10 --seconds 3600`을 실행합니다.
빨간 시연 차량을 제외하고 난수 시드 0~9에서 각각 1시간 차량을 투입합니다.
투입 종료 후 최대 30분 동안 남은 차량의 도착을 기다립니다.
각 실험은 별도 결과 폴더를 사용하므로 현재 GUI용 맵 파일은 바뀌지 않습니다.

물리적인 차량 겹침을 충돌로 정의하며 교차로 내부 검사도 켭니다.
충돌률은 `충돌에 연루된 고유 차량 수 / 실제 투입 차량 수`입니다.
강화학습 평가의 `충돌 에피소드 수 / 전체 에피소드 수`와는 다른 지표입니다.
원시 충돌·차량 주행 XML, SUMO 로그, 시드별 수치와 설정 사본을 `results/traffic_baseline_*/`에 저장합니다.

600m 축척 보정 후, 신호 추가 전 설정에서 10회 측정한 결과:

- 총 투입 7,140대, 총 도착 7,140대
- 충돌 기록 0건, 충돌 연루 차량 0대, 관측 충돌률 0%
- 강제 이동 0건, 급제동 경고 56건 (충돌과 별도 지표)

현재 수요·운전자 설정에서 얻은 시뮬레이션 결과입니다.
설정 수요는 시간당 700대이며, 각 경로가 0초부터 일정 간격으로 차량을 투입하므로
한 시간에 실제 생성되는 차량은 시드별 714대입니다.

## 신호와 어린이보호구역

사용자의 파란 원 표시를 기준으로 다음 세 위치에 신호를 적용했습니다.

| 위치 | 모델의 교차로 | 제어기 |
|---|---|---|
| 제주은행 앞 삼거리 | `bank` | `signal_bank` |
| 동쪽 큰 교차로 | `east_cross` | `signal_east` |
| 북동쪽 해안도로 삼거리 | `godeungeo` | `signal_godeungeo` |

신호 시간은 현장 자료가 없어 **임시 90초 고정 주기**, 황색 3초, 전방향 적색 2초로 설정했습니다.
진행 방향별 현시는 도로 연결과 충돌 관계에 따라 netconvert로 생성합니다.
실제 현시 순서와 동기화가 확인되면 교체해야 합니다.
로터리는 신호 없이 회전 차량 우선을 유지합니다.
졸띠 해변승마 쪽 `inner_e`는 사용자의 정정에 따라 무신호 교차로로 바꿨습니다.

그 아래 삼각형의 빗변 `inner_join`은 **동쪽 큰길 `inner_exit` → 마을·은행 쪽 `inner_e`**
방향의 편도 1차로입니다. SUMO에서는 `inner_join_rev`만 생성하고 반대 방향 Edge는 생성하지 않습니다.
편도 구간에서 `inner_e`에 진입한 차량은 `inner_east_rev`를 따라 **직진만** 가능합니다.
`cross_link`로 좌회전하는 연결은 `seongsan.con.xml`에서 삭제했습니다.
일반 차량 경로는 수정된 연결 관계에 맞춰 다시 계산합니다. 미리보기의 파란 화살표가 진행 방향입니다.

범하다 부근의 `school_north`부터 보룡제과 앞 `west_lower`까지를 양방향 어린이보호구역으로
명시했습니다. 해당 구간의 `school_approach`, `west_bank`, `west_lower` 및 역방향 3개 도로에
30km/h 제한을 적용했습니다. 추가로 은행 남동쪽 CU(`cu_bank`)까지의 `bank_link`와 역방향도
어린이보호구역 30km/h입니다. CU 지점에서 도로를 나누어 구역 경계를 명확히 했습니다.
해당 구간은 별도의 보호구역 설정과 시각 표시를 갖습니다.
운전자 속도 분포의 상한은 제한속도의 1.0배로 두어 과속 편차를 방지했습니다.
미리보기와 SUMO에서는 붉은색 도로 가장자리로 구간을 표시합니다.

보호구역 북쪽 접근로 `hamabo_return`, `start_south`는 사용자 지정 마을 도로 제한인 50km/h입니다.
이전에는 접근로도 30km/h여서 보호구역 진입 시 속도 차이가 거의 없었습니다.
이제 SUMO 운전자 모델이 다음 구간의 30km/h 제한을 보고 진입 전에 감속합니다.
CU 앞 약 36m의 `bank_village`는 보호구역 진입 전 감속 준비 구간으로 30km/h를 적용했습니다.
이는 CU 쪽 진입 시 일부 차량이 순간적으로 30km/h를 초과했던 것을 방지하기 위한 모델 설정입니다.
그 바깥 `cu_village`는 마을 도로 기준 50km/h입니다.
북쪽 경계↔남동쪽 경계의 두 일반 차량 경로에 은행–CU 구간을 경유하게 해 양방향 통행을 확인합니다.
이때 전체 투입 수요는 바꾸지 않습니다.

화면 재생은 시뮬레이션 0.2초당 지연 200ms로, 대략 실제 시간과 같게 조정했습니다.
이전 지연 40ms는 약 5배속이어서 차량이 빠르게 보였습니다.

`python view_map.py --check --seconds 1800`에서 보호구역 최고속도와 신호별 적색 정차 차량 수도 기록합니다.
점검 시 접근로 최고속도와 보호구역 첫 진입 속도를 차량별로 `school_north_entries`에 기록하고,
빨간 시연 차량의 전체 속도 이력을 `generated/ego_speed_profile.csv`에 저장합니다.
`school_zone_max_kmh_by_edge`에는 보호구역 양방향 도로 각각의 최고속도를 기록합니다.
50/60km/h 및 은행–CU 구역까지 적용한 30분 점검에서 보호구역 최고속도는 29.984km/h,
직진 전용 구간 통과는 45회, 금지된 회전은 0회였습니다.

최초 신호 및 속도 상한 적용 후, 무신호·일방통행 정정 전 일반 차량만의 측정(1시간 × 10개 시드):
7,140대 전부 도착, 물리적 충돌 0건, 강제 이동 0건, 급제동 경고 114건.
신호 추가 전 결과와 설정이 다르므로 두 실험의 로그는 별도로 보관합니다.

50/60km/h 변경 전, 무신호·일방통행·북쪽 접근로까지 정정한 후의 측정(1시간 × 10개 시드)은
7,140대 전부 도착, 충돌 0건, 강제 이동 0건, 급제동 경고 55건이었습니다.

50/60km/h·은행–CU 보호구역·직진 전용까지 반영한 최신 측정(1시간 × 10개 시드)은
7,140대 전부 도착, 충돌 0건, 강제 이동 0건, 급제동 경고 58건이었습니다.
